# Детектор светодиодной линии сканера: развёртывание, обучение, эксплуатация

Полное пошаговое руководство: от чистой платы до работающего распознавания
состояний светодиодов сканера (`off` / `red_on` / `white_on`) с отправкой
таймингов по TCP.

> Краткая версия и справка по API — в [главном README](../README.md#детектор-светодиодной-линии-сканера-on-device-ml--tcp).
> Здесь — развёрнутая инструкция «с нуля».

---

## 0. Как это устроено (за минуту)

```
[ Сканер ]  →  [ ESP32-CAM ]                          →  [ Ваш API ]
   LED-линия     ├─ камера RGB565 QQVGA (160×120)
                 ├─ ML-модель (TFLite Micro) по ROI: off / red_on / white_on
                 ├─ машина состояний: длительности ON/OFF + метки времени
                 └─ TCP-клиент → построчный JSON (NDJSON)
```

- Распознавание целиком **на самой ESP32** (никакого внешнего сервера для инференса).
- Веб-интерфейс/поток (`/`, `/stream`, `/capture`) продолжают работать (теперь QQVGA).
- В репозиторий уже вшита **bootstrap-модель** со случайными весами — прошивка
  собирается и весь тракт (тайминги + TCP) работает сразу, но классифицирует
  **мусор**, пока вы не обучите её на реальных кадрах (разделы 6–8).

---

## 1. Что понадобится

**Железо**
- AI-Thinker ESP32-CAM (или клон на WROOM-32, OV2640/OV3660).
- USB-TTL переходник (например HW-597 / CH340G), провода, питание 5В.
- Сканер штрихкодов с подсветкой (например Datalogic) — объект распознавания.
- Штатив/держатель, чтобы жёстко зафиксировать камеру напротив сканера.

**Софт на ПК**
- `arduino-cli` (или Arduino IDE) + ESP32 core `3.3.8`.
- Python 3.9+ для обучения (`ml/`).
- `netcat` (`nc`) и `curl` для проверки (на Windows — через WSL/Git Bash или аналоги).

## 2. Прошивка firmware

### Вариант А — автоматический скрипт (Windows)

```powershell
git clone git@github.com:mikroNQ/ESP-CAM.git
cd ESP-CAM
.\scripts\setup-esp-cam.ps1
```

Скрипт сам поставит `arduino-cli`, ESP32 core `3.3.8`, библиотеки
`WiFiManager` и `Chirale_TensorFlowLite`, найдёт COM-порт, скомпилирует и зальёт
прошивку. Следуй подсказкам (когда поставить `IO0↔GND`, передёрнуть питание).

### Вариант Б — вручную через arduino-cli

```bash
# Однократно
arduino-cli config init
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.8
arduino-cli lib install "WiFiManager"
arduino-cli lib install "Chirale_TensorFlowLite"

# Сборка и заливка (подставь свой порт)
arduino-cli compile --fqbn esp32:esp32:esp32cam CameraWebServer
arduino-cli upload  --fqbn esp32:esp32:esp32cam --port COM30 CameraWebServer
```

> **Контроль памяти.** У клона без PSRAM мало DRAM. В конце компиляции смотри на
> регион `dram0`/`.bss`. Если переполнение — уменьши `DET_TENSOR_ARENA_BYTES` в
> [`CameraWebServer/config.h`](../CameraWebServer/config.h) (модель крошечная,
> ~24–32 КБ обычно достаточно; реально использованный размер арены прошивка
> печатает в Serial: `[det] model ready, arena used N / M bytes`).

## 3. Первый запуск и подключение к WiFi

1. Сними перемычку `IO0↔GND`, передёрни питание.
2. Подключись с телефона/ноута к WiFi-сети **`ESP32-CAM-Setup`** (без пароля).
3. Откроется captive portal (или зайди на `http://192.168.4.1`).
4. **Configure WiFi** → выбери свою сеть, введи пароль → Save.
5. Модуль перезагрузится и подключится к домашней сети.
6. В Serial Monitor (115200) появится:
   ```
   Camera Ready! Use 'http://192.168.1.50' to connect
   LED detector started (enabled=1, endpoint=<unset>:9000)
   [det] model ready, arena used NNNN / 40960 bytes
   ```
   Запомни IP — дальше он `<cam-ip>`.

Проверь, что камера живая: открой `http://<cam-ip>/` — должен быть поток (QQVGA).

## 4. Прицеливание: ROI и экспозиция

Камера должна жёстко смотреть на линию светодиодов. Дальше задаём **ROI** —
прямоугольник, который видит модель.

### 4.1 Подгонка ROI визуально

Открой в браузере:
```
http://<cam-ip>/capture?roi=1
```
Кадр вернётся с **зелёной рамкой** текущего ROI. Двигай рамку и обновляй страницу:
```
curl "http://<cam-ip>/detcfg?roi_x=16&roi_y=40&roi_w=128&roi_h=40"
```
Цель — рамка ровно по линии светодиодов, без лишнего фона. Текущую конфигурацию
можно посмотреть запросом `http://<cam-ip>/detcfg` (без параметров).

### 4.2 Фиксация экспозиции (важно!)

Авто-экспозиция/авто-баланс белого ломают распознавание: при погашенной
подсветке камера задирает яркость (`off` сливается с `on`-состояниями), а
авто-WB нейтрализует разницу красный/белый. Поэтому прошивка **сама фиксирует**
экспозицию/усиление/баланс белого — на старте и переустанавливая каждые ~2с
(сенсор сбрасывается в авто после подвисаний камеры). По умолчанию включено:
`fixexp=1`, `aec_value=250`, `agc_gain=0`, AWB off.

Подстрой `aec_value` под свою сцену (сохраняется в NVS, перепрошивка не нужна):
```bash
curl "http://<cam-ip>/detcfg?fixexp=1&aec_value=250&agc_gain=0"
```
Цель: при включённой подсветке — яркая ровная линия (без пересвета в белое), при
выключенной — тёмный ROI. Проверяй через `/capture?roi=1` и поля
`det_fixexp`/`det_aec_value` в `/status`. Слишком короткая выдержка → линия
«мерцает» (строб подсветки сканера) — подними `aec_value` до стабильной (обычно
≥250). Вернуть авто-режим: `/detcfg?fixexp=0`.

> **Важно для обучения:** датасет (раздел 6) снимай при тех же значениях
> `aec_value`/`agc_gain`/AWB, при которых детектор будет работать, иначе модель
> увидит в бою другую экспозицию, чем при обучении.

## 5. Настройка отправки по TCP и проверка

Укажи адрес своего API (host:port) и включи детектор:
```bash
curl "http://<cam-ip>/detcfg?host=192.168.1.10&port=9000&enable=1"
```
Параметры сохраняются в NVS и переживают перезагрузку.

Проверь поток событий без своего API — поднимай слушатель `netcat`:
```bash
nc -lk 0.0.0.0 9000
```
Подвигай рукой подсветку сканера — в `nc` должны побежать строки:
```json
{"type":"hello","dev":"esp32cam","ip":"192.168.1.50"}
{"ts_ms":12345,"event":"transition","from":"off","to":"red_on","dur_ms":820,"conf":0.97}
{"ts_ms":13190,"event":"transition","from":"red_on","to":"off","dur_ms":845,"conf":0.95}
```
- `dur_ms` — длительность только что **закончившегося** состояния `from`
  (так покрываются и ON-, и OFF-интервалы).
- `ts_ms` — `millis()` на момент перехода.
- `{"type":"dropped","count":N}` приходит после восстановления связи, если
  события терялись из-за переполнения очереди.

> На этом этапе метки (`red_on`/`white_on`/`off`) ещё **неверные** — модель не
> обучена. Главное — что переходы детектятся и JSON доходит. Дальше учим модель.

## 6. Сбор датасета

Весь пайплайн обучения — в каталоге [`ml/`](../ml/) (Python, на ПК).

```bash
cd ml
pip install -r requirements.txt
```

### 6.1 Снять кадры с авто-разметкой по цвету

`collect.py --auto` снимает поток с камеры (`/bmp`), вырезает ROI и сам
раскладывает кропы по `data/off`, `data/red_on`, `data/white_on`; неуверенные — в
`data/_unsure`:

```bash
python collect.py --host <cam-ip> --auto --count 600
```

Снимай в **реальных условиях работы** сканера: включай по очереди красную/белую
подсветку и состояние «выключено», меняй мелочи (угол, блики, дистанцию) —
так модель станет устойчивее.

Если авто-эвристика часто кидает в `_unsure` — подстрой пороги (значения
яркости/красности видны в `review.py`):
```bash
python collect.py --host <cam-ip> --auto --count 600 --off-v 45 --red-margin 20 --white-min 110
```

Альтернатива: если состояние удобно изолировать руками —
`python collect.py --host <cam-ip> --label red_on --count 200` (и так для каждого).

### 6.2 Проверить и поправить разметку

```bash
python review.py
```
Откроется просмотрщик: увеличенный кроп + подсказка эвристики + статистика.
- `o` / `r` / `w` — переметить в off / red_on / white_on,
- `d` — удалить,
- `←` / `→` (или `n` / `p`) — навигация,
- `q` / `Esc` — выход.

Папка `_unsure` показывается первой — пробеги её и раскидай по классам.
Цель — **300–600+ чистых кропов на класс**, примерно поровну.

## 7. Обучение модели

```bash
python train.py --epochs 30
```

Скрипт:
1. загрузит кропы из `data/{off,red_on,white_on}` (папка `_unsure` игнорируется),
2. применит аугментацию (яркость, дрейф баланса белого, гамма, сдвиг
   кадрирования, шум) для устойчивости,
3. обучит крошечную CNN,
4. сделает **int8-квантизацию** и перезапишет
   [`CameraWebServer/led_model.h`](../CameraWebServer/led_model.h).

В конце выведет точность на валидации и параметры квантизации.

> Полезное: `make_bootstrap.py` пересоздаёт пустую модель; `convert_to_header.py`
> конвертит любой `.tflite` в `led_model.h`. Порядок классов и геометрия входа —
> единые в [`ml/model.py`](../ml/model.py); ресемплинг (`Image.BOX`) совпадает с
> box-усреднением в прошивке.

## 8. Перепрошивка обученной модели и запуск

Модель встроена в `led_model.h`, поэтому просто пересобери и залей прошивку:
```bash
arduino-cli compile --fqbn esp32:esp32:esp32cam CameraWebServer
arduino-cli upload  --fqbn esp32:esp32:esp32cam --port COM30 CameraWebServer
```
(или прогони `scripts/setup-esp-cam.ps1` ещё раз).

После загрузки повтори проверку из раздела 5 — теперь метки `red_on`/`white_on`/
`off` и `conf` должны соответствовать реальности. Готово: распознавание и
тайминги уходят на твой API.

## 9. Эксплуатация и мониторинг

- **Текущее состояние** детектора видно в `http://<cam-ip>/status` (поля
  `det_state`, `det_conf`, `det_enabled`, `det_roi`, `tcp_host`, `tcp_port`,
  `tcp_connected`) и в `http://<cam-ip>/detcfg`.
- **Сменить endpoint на лету:** `curl "http://<cam-ip>/detcfg?host=...&port=..."`.
- **Выключить/включить детектор:** `curl "http://<cam-ip>/detcfg?enable=0"` / `=1`.
- **Реконнект TCP** — автоматический, с экспоненциальным backoff; при разрыве
  события буферизуются (очередь), при переполнении — теряются старейшие с
  последующим уведомлением `dropped`.

## 10. Тонкая настройка и диагностика

| Симптом | Что проверить |
|---|---|
| `off` и `red` путаются | Зафиксирована ли экспозиция (раздел 4.2); ROI без лишнего фона. |
| Частые `_unsure` при сборе | Подстрой `--off-v / --red-margin / --white-min` (раздел 6.1). |
| Низкая `conf`, дрожат переходы | Больше данных; увеличь `DET_DEBOUNCE_COUNT` или `DET_CONF_THRESHOLD` в `config.h`. |
| Слишком «залипает» / медленно реагирует | Уменьши `DET_DEBOUNCE_COUNT` или `DET_SAMPLE_INTERVAL_MS`. |
| Не собирается (DRAM overflow) | Уменьши `DET_TENSOR_ARENA_BYTES`; смотри `arena used` в Serial. |
| Нет событий в `nc` | Проверь `tcp_connected` в `/status`, host/port, что детектор `enable=1`. |
| Поток `/stream` тормозит | Норма: одна камера делит кадры между потоком и детектором (QQVGA, без PSRAM). |

Ключевые параметры — в [`CameraWebServer/config.h`](../CameraWebServer/config.h):
`DET_SAMPLE_INTERVAL_MS`, `DET_DEBOUNCE_COUNT`, `DET_CONF_THRESHOLD`,
`DET_TENSOR_ARENA_BYTES`, дефолтные ROI и endpoint.

## 11. Справка по API

| Endpoint | Назначение |
|---|---|
| `GET /` | Веб-интерфейс с потоком и настройками камеры |
| `GET /stream` | MJPEG-поток (QQVGA) |
| `GET /capture` | Один кадр JPEG; `?roi=1` — с зелёной рамкой ROI |
| `GET /bmp` | Один кадр BMP (используется `collect.py`) |
| `GET /control?var=..&val=..` | Настройки сенсора (экспозиция, усиление, ...) |
| `GET /detcfg?...` | Конфиг детектора: `host, port, roi_x, roi_y, roi_w, roi_h, enable, fixexp, aec_value, agc_gain`; без параметров — чтение |
| `GET /status` | Статус камеры + детектора (JSON) |

**Формат TCP-события (NDJSON):**
```json
{"ts_ms":123456,"event":"transition","from":"red_on","to":"off","dur_ms":842,"conf":0.97}
```

**Классы модели** (порядок фиксирован, см. `ml/model.py` и `led_detector.h`):
`0=off`, `1=red_on`, `2=white_on`.
