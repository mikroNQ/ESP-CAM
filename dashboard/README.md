# esp-dashboard — веб-морда таймингов подсветки сканера

Принимает NDJSON-события ML-детектора ESP32-CAM по TCP и показывает в браузере
состояние линии (`off` / `red_on` / `white_on`), живой таймер текущего состояния
и тайминги включения/выключения с минимальной задержкой.

```
[ ESP32-CAM ] --NDJSON/TCP--> [ esp-dashboard :9000 ] --SSE--> [ браузер :8080 ]
```

Только стандартная библиотека Go (никаких внешних зависимостей). Обновления в
браузер идут через **Server-Sent Events** — односторонний push, задержка
ограничена дебаунсом прошивки (~50 мс), а не транспортом. Живой таймер текущего
состояния тикает локально в браузере между событиями.

## Запуск

```bash
cd dashboard
go build -o esp-dashboard.exe .
./esp-dashboard.exe -esp=:9000 -http=:8080
```

Флаги:
- `-esp` — TCP-адрес приёма событий от ESP (по умолчанию `:9000`).
- `-http` — адрес веб-морды (по умолчанию `:8080`).

Затем направь прошивку на этот ПК (IP машины в сети камеры):

```bash
curl "http://<cam-ip>/detcfg?host=<pc-ip>&port=9000"
```

Открой `http://<pc-ip>:8080`. Связь ESP↔сервис видна по индикатору вверху
страницы; переподключение прошивки — автоматическое (с буферизацией событий на
время разрыва, см. поле `dropped`).

## Что показывает

- **Текущее состояние** — крупный цветной индикатор + живой таймер + `conf`.
- **WiFi-сигнал ESP** — полоски + `dBm` + качество словами (отличный/хороший/
  средний/слабый/плохой), и **аптайм** ESP (сброс аптайма = был ребут).
- **Статистика по классам** (`red_on` / `white_on` / `off`): последнее значение,
  среднее, максимум, число срабатываний.
- **Лог переходов** — время, `from → to`, длительность завершившегося состояния
  (`dur_ms`) и уверенность.

Прошивка раз в ~3с шлёт `{"type":"status","rssi","uptime_s","heap"}` (заодно
keepalive). Полуоткрытые соединения (ESP пропала без TCP-FIN) ловятся read-
таймаутом 5с — статус «подключена» не залипает.

## Эндпоинты

| Endpoint | Назначение |
|---|---|
| `GET /` | Дашборд (HTML, встроен в бинарь через `go:embed`) |
| `GET /events` | Поток обновлений (SSE, `event: snap`) |
| `GET /api/state` | Текущий снимок состояния (JSON) — для интеграций |

## Формат входного события (от прошивки)

```json
{"ts_ms":123456,"event":"transition","from":"red_on","to":"off","dur_ms":842,"conf":0.97}
```

`dur_ms` — длительность только что завершившегося состояния `from` (так
покрываются и ON-, и OFF-интервалы). Также обрабатываются `{"type":"hello",...}`,
`{"type":"dropped","count":N}` и `{"type":"status","rssi":-57,"uptime_s":...,"heap":...}`.
